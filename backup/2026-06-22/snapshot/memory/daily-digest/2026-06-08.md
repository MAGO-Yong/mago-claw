## 3. 🆕 新发现/新知识

### QS URL 格式反直觉：job 和 trial ID 顺序是反的

**用户原话**（URL）：
> `https://qs2.devops.xiaohongshu.com/model/production/job/trial/100723/1519291`

**发现**：QS 平台的 URL 格式 `/job/trial/{job_id}/{trial_id}` 中：
- 第一个数字 100723 实际是 **Trial ID**（不是 Job ID）
- 第二个数字 1519291 实际是 **Job ID**（不是 Trial ID）

**Agent 总结**：
> "URL 里 job 和 trial 的顺序搞反了"

**影响**：这导致 Agent 第一次诊断时把 Trial ID 当 Job ID 传入 `qs training diagnose`，返回 NOT_FOUND。修正参数后才得到正确结果。

**记录意义**：后续遇到 QS URL 时应先做参数反转，不要再犯同样的错误。

### 被诊断的任务其实是正常完成的

Trial 100723（用户 emon）的诊断结果：
- 状态：✅ Complete（正常完成）
- 执行时间：1 分 33 秒
- 调度链路：Commit → Running → Complete，完全正常
- 无任何异常事件

**洞察**：用户可能是在帮同事排查，或者链接是给错。这提示 QS 诊断场景下，用户不一定知道任务是成功还是失败，需要 Agent 先确认状态再展开诊断。
