## 🔑 关键决策

### Codex 能力移植方案选择
**决策**：不建议「把 SKILL/CLI 搬过去」，而是走方案 C（Codex 负责编码，OpenClaw 负责发布）

**原因**：
- OpenClaw 的能力来源 = 平台内置工具函数（`cowork_publish` 等）+ Skills（给 Agent 的说明书）
- Codex 的能力来源 = `~/.codex/skills/<name>/SKILL.md` + `~/.codex/prompts/<name>.md`
- **核心差异**：Codex 执行 Skill 时只能跑 Shell 命令，不能调 OpenClaw 的工具函数
- 方案 A（hi CLI 封装）和方案 B（自封装 CLI 脚本）都需要额外维护
- 方案 C 零成本，分工明确：Codex 擅长多文件复杂编码，OpenClaw 有发布工具

**待确认**：用户是否要查 hi CLI 有没有 cowork 相关命令（方案 A 的前置验证）

## 🆕 新发现/新知识

### OpenClaw vs Codex 能力架构差异
| 维度 | OpenClaw | Codex |
|------|----------|-------|
| 工具函数 | ✅ 平台内置（`cowork_publish` 等） | ❌ 无 |
| SKILL.md | ✅ 给 Agent 的说明书，可调用工具函数 | ✅ 仅能执行 Shell 命令 |
| Slash commands | 无 | ✅ `~/.codex/prompts/<name>.md` |
| 能力扩展路径 | 工具函数 > Skills | Skills > Shell 脚本封装 |

**关键发现**：SKILL.md 在不同平台不是通用的——它依赖底层平台提供的能力（工具函数 vs Shell 命令），跨平台移植不能简单复制文件。
