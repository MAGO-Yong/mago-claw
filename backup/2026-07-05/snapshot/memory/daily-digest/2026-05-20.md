# 每日精华 · 2026-05-20（周三）

## 💡 用户的好问题/好思考

### 1. 产品宣发定位：「写已经支持的就好了」
**用户原话**：「这个不需要，我们就是产品宣发，写已经支持的就好了」
- 背景：Agent 在 PR 页面中保留了路线图（Phase 2 开发中 / Phase 3 规划中）和未来愿景区块
- 决策：砍掉 Roadmap、Vision、Case 3（需求演进）三个区块，只保留已上线能力
- 洞察：**产品宣发 ≠ 产品规划**——宣发页面只说「能做什么」，不说「将来做什么」，避免给用户画饼

### 2. 核心卖点不是查询，是操作
**用户原话**：「这里重点不只是查询，重点要表达认领、静默等操作」
- 背景：案例区块最初写的是「移动端查告警」和「安装与授权流程」
- 决策：重写两个 Case，把「一句话批量认领」和「认领 + 静默联动」作为核心叙事
- 洞察：**查是入口，操作是价值**——用户真正想要的不是「看到告警」，而是「在对话框里处理掉告警」
- 配套决策：部署方式（Deploy）区块也从三个卡片简化为一句话——「一份 Skill，多种入口」

### 3. 广告收入排障的维度链
**用户原话**：「消耗下跌、展示下跌、点击/CTR 下跌、CTR 异常、ROI/归因异常」
- 背景：正在为 `adsckexport-service-default` 创建广告收入告警诊断 Skill
- 这是用户实际排查「信息流外流广告整体收入 P0 告警」时的排查维度
- 特点：**顺序排查**而非并行——先看消耗，再展示，再 CTR，再 ROI
- 价值：这是一个可复用的广告收入异常排查 SOP 模板，不只是个案

### 4. 用实时告警作为诊断 Skill 的素材
**用户行为**：直接丢了一个 XRay 告警事件链接 `https://xray.devops.xiaohongshu.com/reddog/event/detail/194554127` 作为诊断 Skill 的素材
- 这是正在触发的 P1 告警（adcenter ToB 服务 RPC 异常）
- 洞察：**用真实的告警事件作为 Skill 创建的素材**，比凭空描述更准确、更高效
- 用户描述的排查路径：Problem → RPC → 服务健康指标（CPU/内存/变更）
