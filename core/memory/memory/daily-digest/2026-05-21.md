## 2. 🔑 关键决策

### 决策一：RPC 异常排查采用三层递进框架

**背景**：adcenter-service-tob 的 `UncheckedTApplicationException` P1 告警

**用户原话**：
> "先排查 problem 看看有没有飙升，以及找到对应 exception 定位下具体问题；然后查看 RPC 等指标判断是否上下游依赖问题，之后查看服务的 CPU、内存、变更等指标，看看是否服务问题"

**决策逻辑**：
1. Problem 异常 → 确认异常飙升 + 定位具体 exception
2. RPC 指标 → 判断是否上下游依赖问题
3. 服务自身 → CPU / 内存 / 变更等指标

这个三层框架可以推广到所有 Problem 类告警的通用诊断模板，是 KR1（通用诊断能力）的重要输入。
