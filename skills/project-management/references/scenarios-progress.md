# 场景参考：项目进展总结

## 模板选择（三选一，优先级从高到低）

| 条件 | 模板 |
|------|------|
| 项目名含4位连续数字（月日，如 `0327`、`1124`） | **模板C（日期型活动项目）** |
| 总结本周/近期进展 | **模板A（周进展摘要）** |
| 总结整体/对照OKR | **模板B（OKR整体进展）** |

模糊时默认模板A，告知用户可切换。

---

## 模板A：周进展摘要

**适用**：本周/近期进展，快速生成结构化摘要。

执行步骤：
1. 执行通用前置步骤（见 api.md），拿 `redocUrl`、`hiGroupId`、UAT
2. 访问 `redocUrl`，读取「四、周进展总结」表格（子项/owner/本周进展列）和风险清单
3. 判断红绿灯：🟢 按计划 / 🟡 风险可控 / 🔴 严重风险需干预
4. 按格式输出（单条消息，禁止分段）

**输出格式：**
```
## 📊 【项目名】进展总结 - 日期

**HIGHLIGHT：** [最关键进展 + 最严重风险，一句话]

**各方向核心进展（X 个模块）：**

🟢/🟡/🔴 **模块名** | 核心进展一句话
🟢/🟡/🔴 **模块名** | 核心进展一句话

**关键风险：**

• 🔴 风险描述 影响说明 建议措施 | Owner: @负责人
• 🟡 风险描述 影响说明 建议措施 | Owner: @负责人

📎 **原始文档：** [文档链接]
```

规则：必须列出所有模块；关键风险只展示🟡和🔴；所有内容压缩在一条消息内。

## 模板B：OKR 整体进展

**适用**：对照项目目标评估整体进度。

**重要原则：**
- ⚠️ **名实相符**：子任务名称严格摘录原文，严禁自行总结或杜撰
- ⚠️ **Checkbox 状态**：`-[x]` = 已完成，`-[]` = 未完成/进行中
- ⚠️ **风险事实原则**：只提取原文明确陈述的风险；里程碑时间已过且 `-[]` 未完成 → 强制标为风险

执行步骤：
1. 通用前置步骤（见 api.md）
2. 找并读取 Kickoff 文档（命名：`KO`/`Kickoff`/`项目立项`），提取 O 和 KR1~KRn
3. 找最新周报，读取各模块进展（`-[x]`/`-[]` 标记、进度百分比、阻塞点）
4. 将周报内容语义映射到 KR 骨架，合并同类项

**输出格式：**
```
**O：{项目核心目标}**

**KR1：{关键结果1}**
- **进展：** {任务A}(进度%) 状态；{任务B} 已完成。
- **风险：** {阻塞点或逾期事实}（无则写：暂无显著风险）

**KR2：{关键结果2}**
- **进展：** ...
- **风险：** ...
```

规则：多任务进展用分号连接；无进展填"暂无最新进展"；禁用"进行了"/"正在进行"等冗余词。

## 模板C：日期型活动项目进展

**适用**：项目名含月日数字（活动/会议/节点型项目）。

执行步骤：
1. 通用前置步骤（见 api.md）
2. 访问 `redocUrl`，找最新推进文档，读取整体状态、各事项进展、待执行动作、时间节点

**输出格式：**
```
**【项目名称】进展同步 - YYYY/MM/DD**

**1. 项目状态**
🟢/🟡/🔴 {整体状态一句话}
⚠️ 风险点：{已发生的风险，无则写"暂无明显风险"}
💡 潜在风险：{可能发生的风险，无则写"暂无"}

**2. 信息同步**
• {模块}：{当前进展，不超过30字}
• {模块}：{进展}

**3. 执行动作**
• @{负责人} 【执行动作】{具体事项}
• @{负责人} 【决策动作】{需拍板事项}

**4. 明确时间**
• {动作描述} → DDL：{MM/DD 或 待确认}

📎 原始文档：[文档链接]({redocUrl})
```
