第一层 · 建立认知
评估到底在做什么 · 不评估的代价

左边先把误解纠过来——评估是看 Agent 在你业务场景下的综合表现；右边对照看，不做系统评估时你正在用什么"替代品"，以及它们的真实代价。

问题定义
不做系统性评估，你在用什么替代它
这些做法在早期可以运转，但随着 Agent 复杂度和流量规模增长，代价会快速放大。
当前做法 实际代价
人工抽查几条对话，觉得还行就上线 一次请求可能调 6 个工具、多次 LLM 推理，人工看不完整链路；边界问题持续漏过到投诉才被发现。
靠经验判断"新版好像比旧版好" 工具调用准确率、RAG 召回质量都可能悄悄劣化。没有量化基准，迭代方向无法被验证。
发现 bad case 后存入 redoc 文档 下次迭代是否修复？同类问题是否再现？没有自动化回归机制，只能依赖人工记忆追踪。
认知建立
评估到底在做什么
评估 = 用可量化的方式，持续回答「Agent 在真实场景里的综合表现是否符合预期」——不只是模型，而是模型 + 工具 + 知识库 + 多轮交互的综合结果。
常见误解 实际上是
评估是测模型能力 评估对象是 Agent 在你的业务场景下的综合表现。同一个模型换工具或知识库，结论可能完全不同。
评估靠人工打分 人工是最后一关，不是全部。自动化先筛出问题样本，人工只看被筛出来的那部分。
有通用评估器可以直接用 不存在。客服看解决率、RAG 看相关性、Tool 看参数准确性——业务 owner 自己定义评估维度。

3.1 第一步永远是定义评估维度

在配任何工具之前，业务 owner 需要先回答一个问题：对你的 Agent 来说，「好」的标准是什么？下面是常见起点维度，但这是起点不是终点——你的业务场景决定哪些维度重要、怎么定义边界。

相关性 正确性 幻觉 安全合规 RAG · 检索召回相关性 Tool · 参数准确性 / 调用必要性 多轮 · 意图穿透

定义清楚「好坏标准」，写成评估器 Prompt——这是评估体系最核心的资产，也是平台无法替你完成的部分。一段真实的 LLM 评估器 Prompt 大致长这样：

# 评估器 · 回答相关性 你是一个严格的 AI 应用质量评估官。请判断【AI 回复】是否 直接、完整地响应了【用户问题】的核心诉求。 ## 用户问题 {{user_query}} ## AI 回复 {{llm_output}} ## 上下文（可选） {{retrieved_docs}} ## 评分规则 - 1.0：完全命中诉求，信息完整且准确 - 0.6：部分命中，主要诉求被回答但有遗漏 - 0.3：方向相关但未真正解决问题 - 0.0：答非所问 / 幻觉 / 拒答 ## 输出格式（严格 JSON） { "score": 0.0 // 0~1，保留一位小数 "reason": "..." // 一句话说清楚扣分原因 }
▲ 示例 Prompt · 真实落地时根据业务调整

3.2 评估器选哪种

两类评估器满足不同场景，绝大多数团队从 LLM 评估器开始；规则成熟后再补 HTTP 评估器。

LLM 评估器 推荐起点

通过 Prompt 描述评分标准，由大模型对每条样本给出 score 和 reason。

优势上手快、无需开发、灵活应对语义复杂判断
注意每条样本消耗 token，不适合全量；评分准确性依赖所选模型
HTTP 评估器

把业务已有的判分逻辑封装成 HTTP 服务，平台调你的服务拿评分。

优势稳定可控、复用已有能力、支持全链路评估
注意需自行开发并维护服务，返回格式须符合平台规范
人工评估不是独立流程，而是接在自动化之后的最终确认环节——自动化先筛出低分样本，人工只处理被筛出的部分。

3.3 创建评估任务 · 接数据 + 字段映射

一个评估任务 ＝ 评估器 ＋ 数据来源 ＋ 调度策略。它把"评估什么"和"什么时候评"绑在一起，跑出来的结果统一回写到实验。X-RAY 提供两条数据通路，对应不同生命周期阶段。

⚡

在线链路数据

基于 ARKAI / ALLIN 等开发的智能体默认上报 AI 链路数据，X-RAY 从真实请求中采集完整链路：用户输入、每个 SPAN 的输入输出（LLM / Tool / RAG）、最终响应。通过 JsonPath 把指定字段注入评估器。

适合：线上持续监控、自动发现 bad case  ·  AI 应用链路规范 ↗
📋

离线数据集

手动整理的样本集，或从线上低分样本自动回流的数据。设计输入/期望输出/标签等字段，映射到评估器变量。

适合：开发验证、上线前基线、版本回归

3.4 看结果 · bad case 自动回流

评估结果有两个视角：实验分析看整体水位（P50/P90/P99 分布、版本对比），实验明细找低分样本（按分筛选、看 reason、跳转完整链路追溯根因）。低分样本根据回流条件自动写入数据集——这是让评估体系越跑越值钱的核心机制。
